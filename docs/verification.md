# Verification

How Stackurity's claims are tested, written in answer to an external review that asked for proof rather than documentation. Every row names the tests that run in CI; the "Found" column lists real defects the tests exposed, each fixed in its own commit in 0.4.0.

| Concern | How it is verified | Found and fixed |
|---|---|---|
| **Background work survives crashes**: feed refresh, inventory upload, notification delivery, periodic tasks and jobs | `internal/crashtest` (CI job `crash`) starts the real server, kills it with SIGKILL at each of these moments and restarts it. Asserts previous data is kept, work resumes or fails visibly, findings are never duplicated, and notifications arrive at least once with a delivery id to deduplicate. See [reliability.md](reliability.md) | 3: jobs killed on every attempt were retried for ever; interrupted feed syncs showed no error; a crash could delay new findings by a day |
| **Several replicas** | `internal/worker` and `internal/store` tests race replicas for periodic tasks, deliveries and rollout releases | 1: two rollout loops could exceed `max_concurrent` (Pro) |
| **Vulnerability matching is correct per ecosystem** | `TestCorpus` in `internal/intel`: 181 cases on 74 real OSV advisories and 6 real Amazon Linux updates (`internal/intel/testdata/corpus`, sources cited) across 18 ecosystems, through the whole sync and evaluation pipeline: affected, fixed, backports, epochs, pre-releases, `last_affected`, withdrawn advisories, unparseable versions | 12, including Rocky Linux packages never matched, RHEL 10 matching nothing, Ubuntu FIPS channels misapplied, Drupal modules never matched |
| **Missing data never looks healthy** | `TestCoverageInvariants`: 16 scenarios (feed never synced, failed, stale, disabled; collection failed, partial, unsupported; stale asset; unparseable version; runtime outside a package manager; never evaluated) each checked through the store and every API that summarises coverage | Releases a feed does not cover (a new Debian or Alpine) and some unparseable versions were shown as clean |
| **Risk priorities are sound** | `internal/risk/scenarios_test.go`: 36 reviewed scenarios pinning priority, SOS rule, every factor and its evidence; property tests for monotonicity, missing evidence, explanations adding up and reproducibility. See [risk.md](risk.md) | 6, including a saved SOS rule silently inheriting conditions from the default rule, and a missing environment scoring like non-production |
| **Policy changes are auditable and reproducible** | Each finding records the policy version that produced it; policy changes are audited with the full policy before and after in the same transaction; tests re-score and compare | Audit was written outside the transaction and held only the new policy |
| **Workspace isolation** | `TestEveryRouteIsClassified` walks the router (149 routes in the paid edition) and fails on any unclassified route; `TestIsolationSweep` tries workspace A's objects with every kind of workspace B credential (each role's session, admin, collector and host-bound agent tokens), including guessed ids, exports, reports, search, audit and jobs. Revoked, expired and downgraded credentials are tested | 4, including a workspace admin able to disable shared feeds for everyone, a workspace admin able to reset an instance admin's password, and cross-workspace references through foreign keys |
| **The loop: how you know it is fixed, and ignoring with care** (0.7) | `internal/store/loop_test.go`: regressed detection (the same finding back after a removal, a new version after a fix) and what is not a regression (an upgrade that stays vulnerable, in either order of the matcher's steps; an intelligence change); snooze until a fix ships returning on a free fix only, with Home's hidden counts still counting it; ignore expiry, limits, and scope everywhere including assets and findings found later; false positives kept rejected by the matcher; check-again lifecycle (request, agent pickup, report, evaluation) with each outcome (passed, partly fixed, still open, expired); "I applied this" resolving nothing. `internal/api/loop_test.go`: who may ignore, ask and decide per role, the inbox per role, audit entries, the agent poll and server-side repository scans. `internal/notify`: issues that came back are urgent once and summarised. The isolation sweep covers every new route and object | An ignore request "until a fix ships" for issues that already have a fix was accepted and silently applied to none |
| **Project isolation** | `TestEveryRouteIsClassified` also requires every route (162 in the paid edition) to declare its project scope, matching the router, which refuses unlisted routes to members with project access only. `TestProjectIsolationSweep` sends every route (2,720 requests in the paid edition) as 17 members of Project A and 6 organisation viewers with a role on it: each role by session, API token and with Project B chosen in the switcher, through a team, through a single-asset grant, after a revoked grant, through an archived project, and as an admin downgraded to project access; they must never see, count, change or delete Project B's objects (assets, findings, fix groups, components, incidents, search, exports, reports, audit, jobs, guessed ids), organisation routes must answer 403, and B's data is compared before and after. `TestProjectAccessRules`: organisation-wide roles see everything, the switcher narrows them, an asset shared by two projects shows in both, an incident spanning projects shows each member only their part, roles from grants act per asset, downgraded grants and leaving a team take effect at once, agent and collector tokens keep working. `TestProjectScopeInDatabase` checks every table with `asset_id` and raw reads and writes on a narrowed connection; `TestProjectMCP` runs every assistant tool with a member's token; `TestProjectRoute` checks notifications limited to a project, including issues that came back, assets connected outside it and overdue issues, and `TestProjectRouteWithholdsOtherAssets` the check every such message passes. The sweep seeds Beta's people, team and Jira link where Alpha can reach them (a grant on the shared database, an assignment, the incident spanning both), reads unfiltered lists and those objects, and also runs as organisation viewers with a role on Alpha; `TestProjectPeopleAndLinks` covers assignment, the directory, tracker links, narrowed incident filters and asset merges. The 0.7 routes (checks, ignore rules, the approval inbox) are in the sweep with Beta's check, ignore request and ignore rule, and `TestProjectAccessRules` checks that a project member cannot ignore on every asset, see or end a rule for every asset that covers none of their findings, or see or decide another project's requests. Removing the narrowing from `findings` alone makes 14 checks fail | Archived projects' names stayed readable by their former members; the unresolved identity-conflict count on the overview counted other projects' assets; members' lists took 0.2 to 0.3 seconds until the scope functions were evaluated once per query (see [projects.md](design/projects.md#performance)). An independent review then found, and these tests now cover: grants on a shared asset audited with the person's email under the asset; assignment to any user id revealing emails in the history; the full directory for organisation viewers with a project role; Jira links and stored priority and escalation of incidents spanning projects |
| **Onboarding: invitations and a quiet first scan** (0.9) | `internal/api/onboarding_test.go`: `TestInvitationSecurity` checks that only organisation admins invite, invalid emails, roles, projects and unknown fields are refused, the token is nowhere in the database (only its SHA-256), the list never shows a link, wrong and altered tokens get the same 410, a request cannot choose the role, organisation, project or email (400), weak passwords are refused without using the link, accepting creates the account with project access only and the invitation's role, a link works once, expired, withdrawn and replaced links stop working, a member is granted at once, and every step is audited. `TestInvitationExistingAccount`: an existing account must be signed in as itself (409 otherwise), API tokens cannot accept, an admin of another organisation joins with the invitation's role only and keeps everything elsewhere, and a member's organisation role and higher project grant are never lowered or raised. `TestInvitationRateLimits`: 10 link attempts a minute per address, 30 invitations an hour per organisation. `TestInvitationEmail`: the link goes through the email channel's SMTP server to the invitee only. `TestOnboardingFlow`, `TestAssetsLandInProject`: the flow's state and steps, and assets added through a project's token, enrollment code or SBOM upload landing in it. `internal/notify/quiet_test.go`: `TestQuietFirstScanEveryPath` connects an asset whose backlog is known exploited and 60 days past every deadline, with a webhook route and a Jira channel, and checks one connected message and nothing else: no urgent message, no Jira issue, no escalation candidate or record, no overdue, newly overdue or not-acknowledged counts, no "new issues" in the summary; a late part of the backlog stays quiet; a new issue afterwards alerts, creates a Jira issue and escalates. `TestQuietBacklogOnlyForNewAssets`, `TestRegressedOnNewAssetIsQuiet`. `actions_test.go`: Assign to me, Snooze and Open on every fix, Slack buttons inside the block limit, email links, and links opened in the route's project. The isolation sweeps cover the new routes (170 in the paid edition; 2,822 requests by project members) and invitations | Jira issues were created for a new asset's backlog (the quiet check ran after them); a new asset's backlog was escalated and reported overdue once its deadlines passed. In the dashboard, a style block left open when 0.7 and 0.8 were merged made the 0.8 styles (the project switcher, the Projects pages) apply nowhere |
| **SSRF and network access** | Tests for every outbound path (Git, webhooks, Slack, Teams, Jira, SMTP, registries, image scans, Kubernetes): loopback, private, link-local, CGNAT, IPv6 forms, metadata addresses, encoded IPv4, redirects and DNS rebinding | 3: zoned IPv6 link-local addresses, encoded IPv4 in Git URLs, DNS rebinding through image scans |
| **Malicious input** | Fuzz targets (seeds run in every build, long runs in the `fuzz` workflow) for SBOMs, every lockfile parser, OSV records, plugin output and Amazon updateinfo; bounded memory and time asserted | 3: output caps never applied; very long versions stalling evaluation; one bad entry voiding a whole scan |
| **Secrets never leak** | Log, error and audit capture tests for tokens, passwords, webhook URLs and credentials in Git URLs | Slack and Teams URLs in delivery errors, typed passwords in the audit log, credentials echoed from malformed URLs |
| **Remediation lifecycle** (Pro) | End-to-end tests with a simulated agent using the real client and fixer: happy path closes the finding only on fresh inventory; revocation before and during dispatch; approval expiry; duplicates (double approval, two replicas, repeated fetches and reports); agent unreachable; lost reports; failed health checks; window closing; policy disabled mid-rollout. Package-manager dry runs tested in real containers (`internal/agentfix/testdata/pkgmanagers.sh`) for apt, dnf, yum and zypper | 7, including a lost report causing a second change on the same host, and in-flight changes never verified after a revoke |
| **Releases, upgrades and recovery** | `release-checks` (on every pull request and required before a release): installs each supported earlier release (the `from:` list in `.github/workflows/release-checks.yml`; 0.2.0, 0.3.0 and 0.3.1 for 0.4.0) with data, upgrades to the new build on the same database, restores a backup into a fresh PostgreSQL, and rolls back to the previous image; releases are signed (Sigstore), carry provenance and an SBOM, and take their notes from [CHANGELOG.md](../CHANGELOG.md) | A restore into a new PostgreSQL left the isolation role missing (fixed in 0.2.0) |

What tests cannot prove: that there is no telemetry and that inspected code is never executed are design properties; [security-audit.md](security-audit.md) explains how the code keeps them and section 4 there maps every stated security control to its tests.
