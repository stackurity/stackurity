### Added

- **Risky AI assistant settings.** AI coding assistants read configuration committed with the code, and some of it runs commands on its own: a Claude Code hook when a session starts, an MCP server when the assistant starts, a VS Code task when the folder is opened. Whoever can change the repository decides what runs on every developer's machine that opens it, and attackers have used this to install backdoors. Stackurity now reads `.claude/settings.json`, `.mcp.json`, `.cursor/mcp.json`, `.cursor/hooks.json`, `.gemini/settings.json`, `.vscode/mcp.json`, `.vscode/tasks.json` and similar files as data and reports what downloads and runs code (critical), MCP servers installed from a Git repository or URL (high), commands that contact a server and settings that send the assistant's requests to another host (medium), and unpinned MCP packages, auto-approval and tasks that run on folder open (low). Commands are shown with keys and passwords masked. Open critical and high findings raise one incident per asset (kind `assistant`, `P1` when critical), sent where new issues go right away. `stackurity scan` checks the files Git tracks and takes `--fail-on-assistant SEVERITY` to stop a pipeline without a server; repositories the server clones and the agent's application directories are checked too (`--no-assistant-config`, or `STACKURITY_NO_ASSISTANT_CONFIG=true` for the agent, turns it off). Collectors send findings only to servers that take them. Security can dismiss a setting the team added on purpose. New: an asset's **AI assistant settings** tab, `GET /assistant-findings`, `GET /assets/{id}/assistant-findings`, `POST /assistant-findings/{id}/dismiss` and `/undismiss`, and the MCP tool `list_assistant_findings`. See [AI assistant settings](docs/assistant-config.md).
