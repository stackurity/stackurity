### Fixed

- **Python inside container images has a version, so an ended Python is flagged.** Images read with `--docker` (running containers, exported through the Docker socket) listed a Python built into the image, such as the official `python` images' `/usr/local/bin/python3.12`, with no version, because nothing in an image is run, and end of life was never checked. The version is now read from the interpreter's files: `include/python3.12/patchlevel.h` (the exact release), else the image's `PYTHON_VERSION` when it is the interpreter's release line, else the release line alone from `lib/python3.12`, reported as `3.12` with evidence saying the patch release is not known. Runtimes in an image with no package database the agent reads (scratch, distroless) are now reported instead of skipped: no package can report them a second time. A distribution's own Python stays one component, its package. On hosts the agent still runs `python3 --version` first, and reads the same files when that fails. See [Docker containers](docs/install.md#docker-containers).
