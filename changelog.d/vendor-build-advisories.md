### Added

- **Vendor builds of Linux packages are checked for vulnerabilities.** A package from a vendor's own repository, such as nginx from nginx.org, Node.js from NodeSource, PostgreSQL from PGDG or PHP from Ondřej Surý, was a coverage gap ("Stackurity doesn't support yet"), because the distribution's advisories describe only the distribution's builds. Vendor repositories ship the upstream release itself (nginx `1.26.2-1~jammy` is nginx 1.26.2), so the products of a new curated catalogue are now matched by that upstream version against the upstream product's NVD records: nginx, Node.js, PostgreSQL, PHP, MongoDB, Redis, MariaDB, MySQL, Elasticsearch, HashiCorp Vault, Consul, Nomad and Terraform. Only configurations NVD records for Linux are applied. Release lines installed side by side (PostgreSQL majors, PHP minors) are fixed each on its own line, and a product installed as several packages is reported once. Enterprise editions, pre-releases and packages with versions of their own (PECL extensions, `libpq5`) stay coverage gaps. Upgrade advice names the upstream release to install from the vendor (new basis `vendor_upstream_fixed`), and the action plan has one "Update nginx to 1.26.3" per host and line. The new feed `nvd:vendor-builds` is created when a host has one of these builds and reads NVD only for the products installed. See [Vendor builds](docs/compatibility.md#vendor-builds).
